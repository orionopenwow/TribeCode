# Make a website: In practice

The site works. Now make it good for real visitors.

## Structure

- **One job per page.** Home says what you do. Other pages answer one question each: prices, work, about, contact.
- **Keep the menu to five links or fewer.** Everything else goes in the footer.
- **Write the first screen last.** Once the rest is written, you know what the headline should promise.

## Words

- Short sentences. Say "you" more than "we".
- Every section ends with something to do: a button or a link.
- Read it out loud once. Fix what you trip on.

## Pictures

- Crop to the subject. Wide banners for the top, squares for grids.
- Give every picture a description. Check my site flags the ones without.
- Keep each picture small enough to load fast on a phone (see Production for sizes).

## Working with others

- Invite a friend with one link and edit together, live.
- Leave comments on the page itself, so the note sits next to the thing it is about.
- Put each change on the **Task Board** so nothing is lost: one task, one owner, one next button.

## Before each publish

1. Open the preview at phone size and scroll the whole page.
2. Tap every button and link.
3. Run **Check my site** and clear the list.
4. Publish. Each publish is a new version, and you can go back to an older one.

## Where it can go

Publish has a **Where it goes** list. It checks the project first, then offers what fits:

- **Play link**: works right away while the tribe's computer is on.
- **Download it**: a zip of the finished page, for any web service you already use.
- **A link that stays up**: a lasting address through your own GitHub sign-in, updated on every publish.
- **Install on phones**: adds an icon and an offline copy, once it has a link that stays up.

The play link is for trying things. Use the lasting link for anything you print or post.
