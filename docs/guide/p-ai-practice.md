# Use AI helpers: In practice

How to get good work from AI helpers, and keep it under control.

## Write a good request

- **Goal:** what should be true when it is done.
- **Where:** the page, screen or file it is about.
- **Limits:** what not to touch.
- **Check:** how you will know it worked.

"Add a pause menu to the game. Do not change the controls. It should open with Esc and with a button on phones."

## Keep changes small

One task, one change you can read in a few minutes. Big requests give big changes that are hard to review and easy to get wrong.

## Review like you mean it

1. Read what changed, not only the summary.
2. Open the preview and try it, at phone size too.
3. Approve, or reply with what is wrong. If it broke something, go back a version first.

## Change what a helper may do

Open **Invite**, choose **Your AI agent** and pick the helper. Choose one of the three, or tick single boxes: chat, docs, tasks, files, website, approvals. It applies at once. Ask Flint "what can my AI do here" for the short version.

## Several helpers

- One helper per tool for each person: your Claude, your Cursor. Connecting again reuses the same one.
- Give each one an area, so two helpers do not edit the same thing.
- Put their work on the Task Board like anyone else's.
- The agents channel shows what they are doing and where they clash.

## Context

Helpers do better when the project says what it is: a clear vision, up-to-date tasks, and notes on decisions. Keep those current and you repeat yourself less.

## When it goes wrong

- It keeps failing the same way: stop, describe the problem in a new request, add what you already tried.
- It changed too much: go back a version and ask for a smaller step.
- You are not sure: ask Flint "what should I do next".

## Privacy

Check what a helper can read before you connect it. Keep keys and passwords out of the project's files. A helper's key is shown once, to you only. Nobody else in the project can see it.
