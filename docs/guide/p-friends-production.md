# Work with friends: Production

Checklists for a larger team: several people and AI helpers on one product.

## Team shape

- [ ] Roles written down: owner, leads per area, reviewers, release owner
- [ ] Each area has a lead and a stand-in
- [ ] A page for newcomers: goal, rules, how to get a first task

## Ways of working

- [ ] Working agreement: hours people overlap, reply times, where decisions are written
- [ ] One place for decisions, with date, reason and who agreed
- [ ] A weekly plan and a weekly show-and-tell
- [ ] Written check-ins replace status meetings

## Change control

- [ ] Every change is a task; nobody changes the main line without a review
- [ ] Review rules: who can approve what, and how fast
- [ ] Clashes are settled by the area lead, then written down
- [ ] Protected areas (money, release, sign-in) need two approvals

## Versioning

- [ ] One numbering rule for versions; a change note for each
- [ ] Freeze before a release: fixes only
- [ ] The last good version is known, and going back has been tried

## Quality gates

- [ ] Definition of done per kind of task
- [ ] Checks before publishing: tests, phone size, accessibility, performance budget
- [ ] Bugs have steps, severity and an owner; the worst are fixed first

## Access and safety

- [ ] People get only the access their role needs; reviewed monthly
- [ ] Invites are per person; old links are turned off
- [ ] Leaving checklist: hand over tasks, remove access
- [ ] Rules for behaviour, and someone to go to when they are broken

## AI helpers on the team

- [ ] Each helper belongs to a person who answers for its work
- [ ] Helpers take tasks like anyone else and are reviewed like anyone else
- [ ] Limits on what helpers may change are written down
