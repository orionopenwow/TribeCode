# Use AI helpers: Production

Checklists for teams that rely on AI helpers for real work.

## Roles and ownership

- [ ] Every helper has a named person who answers for its work
- [ ] Each helper has a written role, an area, and a list of what it must not change
- [ ] Sensitive areas (sign-in, money, release, personal data) need a person to write or closely review

## Pipeline

- [ ] Helpers work from tasks with a goal, limits and a check
- [ ] Every proposed change is reviewed by a person before it goes in
- [ ] Automated tests run on helper changes exactly as on people's
- [ ] Changes are small enough to review in under 15 minutes
- [ ] Each change records which helper made it and who approved it

## Quality

- [ ] A definition of done that includes tests, phone size and accessibility
- [ ] Performance budgets checked after helper changes
- [ ] A sample of approved changes is re-read each week to catch drift
- [ ] Repeated mistakes become written rules in the project's context

## Context and versioning

- [ ] Project context kept current: vision, structure, rules, decisions
- [ ] The helper, its version and its settings are noted per release
- [ ] Prompts and rules that matter are kept in the project and versioned
- [ ] Going back a version is tried and quick

## Safety and privacy

- [ ] Access is the least each helper needs; reviewed monthly
- [ ] No keys, passwords or personal data in requests or files
- [ ] You know where each helper sends data, and the people affected agreed
- [ ] Licences checked for anything a helper brings in
- [ ] Generated pictures, sound and words checked for rights before release

## Cost and limits

- [ ] Usage watched per helper; a limit set per week
- [ ] A plan for when a helper is unavailable: the work can be done by hand

## Disclosure

- [ ] Store and platform rules on AI-made content read and followed
- [ ] The team agrees what to tell users about AI use
