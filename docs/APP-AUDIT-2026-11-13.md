# App audit, 2026-11-13

Branch `feat/audit` (from `integ6`, with drag-and-drop merged in). It covers everything built since v0.31.0 that is not released yet: the one Flint chat and flintmax, the create-a-tribe flow, folder homes with GitHub / shared-folder sync and Versions, auth2 sign-in, tabbed Settings, Invite your Claude, the free-AI bridge, the dashboard band, the 19 widget cards, the Work redesign, the hardening pass, the demo intro, the sign-up nudge and drag-and-drop.

This page is written for the owner. Engineers: the walker is `app/test/audit_walk.py`, the regression test is `app/test/e2e_audit_fixes.py`, the removals are listed in `docs/UI-CLEANUP.md`.

## 1. What was checked, and how

**A robot walked the whole app and clicked everything.** `audit_walk.py` opens every destination in the router's list, every page of your dashboard, every Settings tab and 20 sheets (create a tribe, People, Friends, Invite your Claude, the home pill, Versions, plans, Flint's page, the free-AI bridge, the + Add picker, Help, the Guide, Ctrl K, the profile menu, the + menu, sign-up, the preview, the website designer, Flint's chat, the inbox). On each one it clicks every visible button, tab and menu item, closes whatever opened with Esc, and writes down anything wrong. Buttons that delete, sign out, pay, upload, record or leave the app are skipped.

It did this in four situations and two screen sizes:

| Situation | Desktop 1280 | Phone 390 |
| --- | --- | --- |
| No tribe (then a project on this device, which the walk creates) | WALK_none_desktop | WALK_none_phone |
| A hosted tribe, as the host | WALK_host_desktop | WALK_host_phone |
| The same tribe, as a member (builder) | WALK_builder_desktop | WALK_builder_phone |
| The same tribe, as a spectator | WALK_spectator_desktop | WALK_spectator_phone |

Totals: **WALK_TOTAL_ROUTES page visits, WALK_TOTAL_CLICKS clicks, WALK_TOTAL_API server calls**. On every page it looked for: crashes, console errors, server calls that failed (other than the expected "not signed in / not allowed / not found"), sheets that Esc does not close, text under 12px, clipped text, sideways scroll, buttons off screen or covered, "Loading…" that never ends, raw error text ("Failed to fetch", "undefined", "NaN") and the same id used twice.

**A scan for old code still wired in.** Scripts compared `index.html`, the offline file list, every stylesheet and every script: files nothing loads, globals nothing calls, ids that code looks for but nothing draws, CSS for classes nothing uses, two stylesheets (or two rules) fighting over one class, shortcuts registered twice.

**Hand checks of the joins between features** built by different agents this week (section 4).

**Tests.** Run one at a time after the fixes, all passing: `e2e_truth`, `e2e_no_stale`, `ui_smoke`, `bundle_test`, security 1 to 6, `e2e_audit_fixes` (new), `flintkb_test` (new), `e2e_work_v2`, `e2e_settings_tabs`, `e2e_dropzone`, `e2e_guide`, `e2e_flint_local`, `e2e_demo_watch`, `e2e_signup_nudge`, `e2e_notify`, `e2e_presence`, `e2e_versions`, `e2e_folder_home`, `e2e_ship_sync`, `e2e_ai_bridge`, `e2e_tasks_accept`, `e2e_session`, `e2e_fresh`, `e2e_fresh_open`, `e2e_setup_local`, `e2e_invite_claude`, `e2e_tribe_flow`, `e2e_mobile2`, `e2e_nav`, `e2e_fleet`, `e2e_site2`, `e2e_chat2`, `e2e_captures`. The full `npm test` was not run (three agents share a 2-core machine); run it once on the integration branch before the release.

What the walk can't judge: whether a click did the *right* thing (it only sees that something changed), real devices (iPhone Safari, the Windows desktop app), real GitHub, real payments, real push.

## 6. Holes: what a user would expect and not find

Ranked by how much it hurts a first week of real use.

1. **You can't pay.** Plans and credit packs show prices; nothing can be bought. (Needs your Stripe or Paddle account.)
2. **No second step at sign-in.** No two-factor codes, no passkeys. Accounts with no password still exist on local hosts.
3. **Too many ways to invite a person.** The tribe link, a one-time invite, a guest pass, a project invite, "Invite a friend" on Home (starts a new project), People › Invite, the create flow's invite step, QR. Each is fine; together a new person can't tell which to use. See `docs/screenshots/audit/invite-sheet-desktop.png`.
4. **Two Claudes and an eager invite** (section 5, #1 and #2).
5. **The first screen asks five things at once.** A new project's dashboard shows Set up your preview, Needs attention (GitHub, backup), Getting started in 5 steps, Your focus and Connect your AI. See `project-dashboard-desktop.png`.
6. **A project on this device is a second-class place.** No Guide, no website templates, no Versions, no notifications settings, no widget picker; each now says so calmly, but a person who started "on this device" hits these walls in the first ten minutes.
7. **Three "versions".** Versions (the project's history), Website versions / Saved (the designer), and versions of a screenshot in Visuals. Same word, three places, different restore rules.
8. **Signed out means stuck.** A signed-out device now says so, but there is no "Log in again" button in that message.
9. **Build status is only as real as what agents report.** The dashboard's build and preview state comes from `POST /api/dash/signal`; nothing runs the project's own tests or reads CI by itself.
10. **Work is one tribe wide.** Public gigs go out through GitHub; nothing fetches other tribes' feeds yet (Work Phase 2).
11. **Push to a closed phone app** needs Apple and Google push services; today it is Web Push only.
12. **Email without the host's own mail server** is not possible, so sign-in links and email notifications are off for most hosts.
13. **Phones:** a few tap targets are under 28px (the Home breadcrumb 63×22, colour swatches 24×24, People's filter chips 23px tall, the demo pill 26px tall).

Sketches:

1. **Payments.** Fill in the `checkout()` hook in `app/ui/premium.js` to create a checkout session on the server, and add `POST /api/premium/webhook` that verifies the provider's signature and calls the same `set` path `PUT /api/premium` uses today. Credit packs become real line items; the plans pop-out's buttons stop being informational. Risks: webhook replay (store event ids), refunds, tax. Nothing to build until the account and prices exist.
2. **Two-factor and passkeys.** TOTP needs no outside service: a secret per account (stored hashed-at-rest in `.tribe/accounts`), a QR in Settings › Account & sign-in, ten recovery codes, and one more step in `auth2.js` after the password or provider. Passkeys use the browser's WebAuthn with the host's address as the relying party, so they only make sense on a stable public address. Both change the sign-in flow, so they get their own security test file and a review.
3. **One invite sheet.** Keep one sheet with one question first: "Who?" → A friend (the tribe link, with QR and "one-time instead") · A guest for a day · Your Claude. Home's "Invite a friend", People › Invite, the project menu and the create flow all open it at the right choice. The server APIs stay as they are.
4. **One Claude per person, and OAuth for claude.ai.** Make Invite your Claude the one way a person's Claude joins, and show an existing Connect-your-AI Claude inside the same sheet as "already connected" instead of minting a second member. Create the member when the person copies the setup, not when the sheet opens. For claude.ai on the web, add the small OAuth flow MCP clients expect (authorize page on the host, a code, a token) so the key is no longer part of the URL.
5. **Real build results.** A tiny runner on the host: when a project has a `package.json` test script (or a `tribe.json` check), run it after each ship in a child process with a time limit, and post the result to the same `/api/dash/signal` agents use. Optionally read GitHub's check runs for the project's repo. The Build status card and Needs attention then show facts, not reports.
6. **On-this-device parity.** Bundle `docs/guide/*.md` and the website template list into `app/ui` at release time (a build step that writes two JSON files and adds them to the offline list), and let `offline.js` answer `/api/guide` and `/api/site-library` from them. Local Versions can be snapshots of the device's project state in IndexedDB.
7. **A calmer first dashboard.** Keep the preview band. Under it show one card, the next step of the five, and fold Needs attention's setup gaps (GitHub, backup) into that list until the project has real activity. Hide Your focus while nothing is assigned.
8. **Flint tier 1.** A 8 to 30 MB embedding model, downloaded once on Wi-Fi, replaces word matching in "did you mean", the knowledge base and taught phrases, and adds search by meaning across docs, tasks and chat. Everything still works without it.
9. **Work Phase 2.** A scheduled, careful fetch of each subscribed tribe's signed feed (size cap, timeout, no private addresses), stored on disk and merged into Gigs › Public. The signing and verifying half already exists (`server/workfeed.js`).
10. **Native push.** Needs the store apps and your Apple/Google keys; the server side is one more channel next to Web Push in `server/notify.js`.

## 8. Design recommendations (not implemented)

Nothing here was changed in code. Screenshots are in `docs/screenshots/audit/` (desktop and phone for each).

**Consistency**
- **One word, one thing.** "Versions" (three meanings), "Home" (your dashboard, a project's Dashboard, and the home pill meaning where a project lives), "Invite" (a friend, a guest, a Claude). Suggest: *History* for the project, *Saved* for the designer, *Shots* for Visuals; *Where it lives* for the pill.
- **Sheets come in three shapes.** The bottom-sheet family (`ph-sheet`: create a tribe, home pill, Versions), the centred modal (`modal-card`: invites, Invite your Claude), and one-offs (the free-AI bridge, plans, Flint's page). Pick the bottom-sheet family for anything with steps and the centred modal for one decision; give all of them the same header (eyebrow, title, X on the right) and the same Esc rule.
- **Small text.** Eyebrows are 10.5px by rule, but the same size has spread to things that are not eyebrows: plan tags (10px), licence and kind tags in the Marketplace and Studios (10 to 11px), settings section headings (11.5px), the TEST badge (9.5px). Suggest a floor of 11px for mono uppercase labels and 12px for everything else, and one `--label` token.
- **Buttons in a row.** The invite sheet mixes filled, outline and chip buttons in one block (`invite-sheet-desktop.png`); the Work tiles look like buttons but the abilities row next to them has a real button. One primary per card.

**Crowded screens**
- **A new project's dashboard** (`project-dashboard-desktop.png`, `-phone.png`): five "do this next" units. One at a time (suggestion 7).
- **The right panel** shows Your focus, Connect your AI and AI Insights on every dashboard page, including Work and Files (`work-desktop.png`), where it competes with the page. Suggest: closed by default outside Home, remembered per page.
- **The invite sheet** (`invite-sheet-desktop.png`): four ways to share, the tribe link with rename / new link / turn off, a one-time invite with three menus, and a QR, in one scroll.
- **Invite your Claude after the first open** (`invite-claude-phone.png`): the permissions take the screen while the one thing a returning person wants ("show me the setup again") is a secondary button with a warning.

**Hierarchy**
- Home's "Good morning" header, the preview band and Quick start all read as heroes (`home-desktop.png`). The design rules say one hero per screen; the band should win, the greeting can shrink to one line.
- Settings on phones (`settings-profile-phone.png`): the preview card ("Pushed the new title screen… Ship it") is the first thing in Profile & look and looks like real content. Label it "Preview" or move it under the controls it previews.

**Empty states**
- With a project on this device, several places now say "…once this project has a home". Give them one shared card with one button: *Choose where it lives*.
- People › Everyone shows "0 online" above a list where you are online. Say "Just you here" when alone.
- The Guide without a server, Work without a tribe and Versions without a project each word the same idea differently; one pattern (title, one line, one action, "How it works").

**Motion**
- Sheets open and close in different ways: the home pill's sheets fade out over 160 ms, the People panel slides, the centred modals cut. Use the same in and out (`--dur-quick`, `--ease-out`) for every sheet, and nothing under reduced motion.

**Phones**
- Tap targets under 28px: the Home breadcrumb, colour swatches, People's filter chips, the demo pill. Suggest 36px minimum, as the widgets already do.
