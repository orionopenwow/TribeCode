# Review after v0.29.0 (2026-11-11)

This review looked for gaps in `main` at bf0e8d6 (v0.29.0) after the parallel merges: router, accounts, local setup, Flint, ✦ AI basics, inspiration board, fleet, PWA, moderation, preview editing, Work, templates, Premium and the run-through. Branch: `feat/review`.

Regression tests for the fixes are in `app/test/security4_test.py`, which is now in `npm test`. Each check in it was confirmed to fail against the old code.

## How it was checked

- **Client → server routes.** A script pulled every `api('/…')` / `fetch('/api/…')` call in `app/ui` (853 calls) and sent each one, with its method, to a throwaway server as the host. It recorded every generic "not found" answer. Every hit turned out to be a false positive: a dynamic id cut off by the extraction, a `ctx.api` website wrapper, or `/api/dev/stamp`, which only answers in dev mode. **No client call is missing a server route.** The reverse check (server routes that nothing calls) was not done; the routing is spread across about 60 modules, which makes a reliable script hard to write.
- **Globals.** Every `TribeX` that is used is also defined. Two exceptions, `TribeMoney` (academy.js:40) and `TribeNotes` (plusmenu.js:117), are optional and guarded: the code falls back to `go('money')` and to `@secretary note`.
- **sw.js SHELL.** All 309 entries exist, and every script and stylesheet in index.html is in SHELL. Files outside SHELL are there on purpose: the worker, the public pages, `support-contact.js`, `inapp.js`.
- **XSS.** A scan for `innerHTML` / `insertAdjacentHTML` template interpolations in the new UI files found no user data without `esc()`. Thumbnails are base64 `data:` URLs, and counts are numbers.
- **Security.** The listed routes were read by hand: talent, rituals, siteflint, flintrun, inspo/freesound, accounts, moderation, PWA share target, aibasics refine/extract/tags, the Blender stub and the fleet.

## Findings, by severity

### High

**1. Another member's private inspiration board can be read and written.** Fixed in 06d2493.
- Where: `server/inspo.js:332` (route).
- What happened: personal boards are stored as the project id `u-<member id>`. `api()` lets an unknown `?project=` fall back, and the route accepted any `u-…` id. So any member, including a friend invited to only one project, could read, add to, recolor and delete items on someone else's personal board with `?project=u-<their id>`. Member ids are visible in presence.
- Fix: a `u-…` board must be the caller's own, otherwise the answer is 404.

### Medium

**2. Proof-of-work ZIPs leak across projects.** Fixed in 8874a31.
- Where: `server/flintrun.js:183-205`.
- What happened: `GET /api/flint/proof` and `/proof/file` listed and served every ZIP in `<tribe>/exports/` to any member. These ZIPs contain a project's full code. A friend invited to project A could download project B's code, and any builder could overwrite the host's ZIP by saving under the same name. The manifest also named every member of the tribe, and the absolute host folder path went to everyone.
- Fix:
  - `exports/.owners.json` records who saved each ZIP. Only the saver and the host/admins list or download it.
  - Saving over someone else's ZIP returns 409.
  - The manifest is limited to `presenceFor(me)`.
  - `dir` and `path` are sent to the host only.

**3. ✦ file tags could be written into another project.** Fixed in 477b972.
- Where: `server/aibasics.js:62`.
- What happened: `PUT /api/ai/tags` took `body.project` without a visibility check, so a member could write tags into a project they can't see.
- Fix: the project must exist and be visible to the caller.

**4. Accounts with no password log in with the username alone.** Proposed fix.
- Where: `server/accounts.js:139`.
- What happens: accounts made by `syncMembers()` and sign-ups without a password are accepted on username only. Today this is limited, because accounts are local-only and flag-gated, and a passwordless login can't sign in as a member. Once accounts are reachable remotely, it is an account takeover.
- Proposed fix: require a password or a linked provider before `TRIBE_ACCOUNTS=1` goes beyond local. Added to docs/LAUNCH.md. Not changed here, because another agent owns accounts.js.

**5. The exports folder has no total cap.** Proposed fix.
- Where: `server/flintrun.js:198` (`POST /flint/proof/save`).
- What happens: any builder can save unlimited 120 MB ZIPs under new names and fill the host's disk.
- Proposed fix: a per-member count or byte cap (for example 10 ZIPs or 500 MB), plus `limited()`.

### Low

**6. The fleet let a member task agents outside their project.** Fixed in 31fc6ab.
- Where: `server/agentshub.js:317`.
- What happened: `POST /api/agents/fleet/<id>/task` accepted any agent id.
- Fix: the agent's owner must be in the current project (`ownerOk`). Giving tasks to teammates' agents in the same project still works, as the UI intends.

**7. The Blender "run" command could carry shell syntax.** Fixed in 8874a31.
- Where: `server/flintrun.js:181`.
- What happened: the model name only had its `"` removed, so `$( )` and backticks could reach a command people paste into a shell. The `.py` script itself was already safe.
- Fix: the command keeps only safe path characters.

**8. Premium is enforced in the browser only.** Proposed fix.
- Where: `app/ui/premium.js:38-43`.
- What happens: plan and trial live in `localStorage`, so clearing storage resets the trial. This is fine while nothing is sold (soft gates by design).
- Proposed fix: verify server-side in the `TODO(payments)` webhook before charging.

**9. Outbound fetches have no rate limits.** Proposed fix.
- Where: `server/inspo.js:331,339` (search, link) and `server/talent.js:576` (`/talent/public?refresh=1`).
- What happens: any builder can make the host fetch from Openverse, Wikimedia, Freesound, link pages or jsDelivr as fast as they like. SSRF protection is in place (`embeds.safeGet`, the URL map), so this is about cost and noise, not reach.
- Proposed fix: `limited(req, 30)` on these routes.

**10. The ✦ poll does more work as the board grows.** Proposed fix.
- Where: `app/ui/aibasics.js:204`.
- What happens: one 700 ms interval while the tab is visible. It is not a leak (one instance, page-lifetime), but each tick runs a `:scope >` query on every `#board .task`, so its cost grows with the board.
- Proposed fix: query `#board .task[data-id]:not([data-ab])` and mark the row, or scan only when `data-view` is `tasks`.

**11. Router Back after closing the preview depends on a time window.** Proposed fix.
- Where: `app/ui/router.js:106`.
- What happens: a `popstate` within 1.5 s of leaving the full-screen preview is treated as the preview's own Back. A quick real Back in that window is ignored.
- Proposed fix: have preview.js mark its own history entry (it already sets `state.pvw`) and check that instead of the clock.

**12. Rituals "run now" and agents.** Proposed fix.
- Where: `server/rituals.js:108`.
- What happens: agents can create and run rituals, which post to chat. Runs are de-duplicated per day, so spam is bounded.
- Proposed fix: say in SECURITY.md that agents can do this, or limit it to people.

### Loops not closed

**13. LAUNCH.md was out of date.** Fixed in the review commit.
- "AI consent (polish wave)" and "account deletion on the web (polish wave)" are both built (`aiconsent.js`, `delete-account.html`).
- "export and delete (`GET/DELETE /api/account`)": delete is built, but `GET /api/account` exports nothing. The entry now says so, along with finding 4.

**14. Four suites are not in `npm test`.** Proposed fix.
- Suites: `e2e_assets.py`, `e2e_inspo.py`, `e2e_site_edit.py`, `e2e_site_lang.py`.
- Either add them to `npm test` or delete them if `e2e_inspo_board` / `e2e_preview_polish` supersede them.
