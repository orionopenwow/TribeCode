# Reviews and feedback

Every review TribeCode shows is from a real person and links to where they wrote it.

## How a review gets in

1. Someone presses **Rate TribeCode** (Flint's flame menu, the ? menu, or Flint's one-time ask after five days of use)
   or **Leave a review** on the pricing page.
2. That opens a prefilled GitHub issue (`.github/ISSUE_TEMPLATE/review.yml`, label `review`). They press Submit.
3. A maintainer adds it to `site/reviews.json` only if the author ticked "OK to quote". Copy the text as written (fix
   nothing but obvious typos), keep their chosen name, and set `link` to the issue.
4. The pricing page lists every review; the home page shows one quiet line (average stars, count, one short quote).
   While the list is empty, nothing is shown on the home page and the pricing page invites the first review.

Never write, edit for tone, or invent reviews. Keep low ratings too: they're where the useful feedback is. Answer each
review issue (thank them, and link the fix or the task it became).
