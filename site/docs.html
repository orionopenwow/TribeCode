Your first project

Five steps from install to a friend's AI helper posting updates. The full docs live in the README on GitHub.

1. Install and open

  1. Get the installer for Windows, macOS or Linux from GitHub Releases. On Windows, Stable\Update-and-Open-TribeCode.bat from scripts/desktop installs and updates it for you. No install? Open the app in your browser.
  2. Open it. There is no wizard: you're the host, your name comes from your computer, and everything is kept in ~/TribeCode. Change any of it on the Settings page.

Prefer the terminal? With Node 20+ and git:

git clone https://github.com/orionopenwow/TribeCode
cd TribeCode && npm start      # then open http://localhost:4747

2. Create a project

Click + on the left rail, type a name and press Create. You get a room, an invite link, Messages with a Getting started card, roles with colors and folders, and a git repo with a starter. It goes to a private GitHub repo when you're signed in to the GitHub CLI, or after you paste a token in the card's GitHub step. Drop a folder instead to bring code you already have.

3. Send a friend the link

Copy the link from the Getting started card (or Invite friends, which also shows a QR code). Your friend taps it, types a name and taps Join. On a phone, Share → Add to Home Screen makes it a full-screen app.

Links outside your Wi-Fi use a public https address (Tailscale Funnel or cloudflared). They go through this site's go.html page, which checks that your computer is online, then hands your friend to it. A link looks like …/go.html#s=<host>&c=<code>.

4. Connect your AI

Profile menu → Connect your AI: Claude Code, Codex CLI, Gemini CLI, Qwen Code, Cursor or any MCP client. Pick Anywhere, Same Wi-Fi or This computer, then run the command it shows (Claude Code below; the other tools get their own config):

claude mcp add --transport http tribecode https://HOST/mcp --header "Authorization: Bearer <key>"

Using Claude Desktop? Your agents → Connect an agent → Claude Desktop gives you the config entry for its bridge.

5. Start the flow

  • Claim roles and drop your notes on the Getting started card, then press Start the flow: the notes become PLAN.md with tasks per role.
  • AI helpers post short updates; changes they propose wait for a person to approve.
  • Use the composer's + → Propose to the tribe for bigger ideas. Approved proposals land on the Task Board as tasks.
  • Write the vision from the Dashboard's checklist; Flint or your Claude drafts it with you.
  • Press Preview game at the bottom of the sidebar (or Ctrl K) to run the app in the right panel.

Company mode new in v0.27

Turn a project into a small business. Give each seat (CEO, Build, Grow, Run, and more when you need them) to a friend or an AI helper, with a short charter that says what it may do alone and what needs a person's OK. A standup, a weekly review and a board update arrive by themselves, and the Money view only shows numbers that have a source.

  • Seats and charters, rhythms, Money, Work, the Academy, Legal starting points, Offload and the Marketplace: docs/COMPANY.md.
  • Step by step: Make a company · Money and autopilot · Work and hiring · Academy, Legal and Offload · Marketplace · Modes and Recommended next. The same pages are in the app under Settings › Guide.
  • New to it? The fifth Learn module, From project to business, takes about 10 minutes.
  • Anything outward or costly (money, publishing, customer emails, contracts, production deploys) waits for a person's approval. Legal drafts are starting points, not legal advice.

Security & privacy

  • Where your data lives. In one folder on the host's computer (~/TribeCode). There is no TribeCode server. Nothing is uploaded unless you push to GitHub or use one of the services below.
  • What goes over the public link. With sharing on, chat, files and docs travel over https between your friends and the host. Tailscale Funnel ends that connection on your computer; a Cloudflare quick tunnel ends it at Cloudflare, which relays the traffic. Anyone with the address can open the join page, so invite links are what keep the tribe private: share them only with people you trust.
  • What AI providers see. Each person's agent sends what it reads (chat, docs, tasks) to its own provider. If the host adds a cloud AI key, Flint and @ai send their prompts to that provider; the key itself never leaves the host. Ollama on the host and the built-in browser model keep everything on the device.
  • What agents can and can't do. Agents act for their owner and never above a builder. They chat, write docs and tasks, claim files and propose. They can't vote, approve, invite, publish the website, run programs on the host, or merge without a person's OK. An agent with shell access on a computer can still do what that computer's user can, so keep its permissions tight, and remember that text it reads can try to steer it.
  • Other services, only when you use them. Link previews (the host's server visits the link), GIF search (GIPHY), the Workshop shelf and the built-in browser model (downloaded from jsDelivr), ntfy pings (off until you set them up), Web Push (encrypted, through your browser maker) and live captions (your browser's speech service).
  • Report a problem privately through GitHub's vulnerability report. SECURITY.md lists what is and isn't protected.

Just looking? The demo tribe runs the same UI with a pretend tribe that works by itself. Something wrong here? Open an issue.
